House Band

Music written as code. Your samples. Your songs.

An LLM (or you) writes the score as readable JSON. House Band checks it and plays it, the same way every time. The model never touches the audio.

One real run through Composer's Desk, start to finish: the prompt, the JSON the model sent back, and what House Band rendered from it. There is no prompt-to-audio step: the model only writes the score.

1 The prompt

A late-night diner jukebox tune for a small town after closing time. Warm, a little lonely, a slow walking bass, brushed drums, and a lead that sounds like someone humming to themselves on the drive home.

Direction brief

Slow, warm, small-hours. Tempo around 84. Brushed kit. One clear hummable lead phrase in A that answers itself in B; walking bass that heads home to the tonic at the end. Leave space: rests matter more than notes.

Sections

  • A (4 bars): Introduce the hummed lead phrase over pad and walking bass; drums barely there.
  • B (4 bars): The answer: lead climbs, pluck counter-line enters, drums fill out.
  • C (4 bars): Back to A's phrase, resolved; bass lands home and a bell closes it out.

    Bring your own samples

    Point a folder of WAV files at House Band, check the role report, then render. Blue marks your material; grey roles fall back to a synth kit.

    1. house-band samples scan ~/Samples/my-drums
    2. Check the report, edit the mapping if needed
    3. house-band render my-song.json --kit-map tr707=user:my-drums -o my-song.wav

    How it works

    A score is authored data. The renderer is deterministic within a pinned toolchain and writes a WAV plus a custody manifest. 

    {
  "schemaVersion": "1.0.0",
  "kitVersion": {
    "semver": "1.1.0",
    "sha": "b2709519f2faf8481de28e0a5e9912cd2e80ae9e290fdfca88915c0377aaf773"
  },
  "seed": 42,
  "tempo": 96,
  "sampleRate": 44100,
  "register": { "name": "kit-demo", "briefRef": "docs/REGISTER-KIT-DEMO.md" },
  "tracks": {
    "pulse": {
      "len": 16,
      "steps": [
        { "i": 0, "voice": "kick", "opts": { "vol": 0.28 } },
        { "i": 8, "voice": "snare", "opts": { "vol": 0.1 } },
        { "i": [0, 4, 8, 12], "voice": "hat", "opts": { "vol": 0.035 } },
        { "i": 0, "voice": "bass", "note": "C2", "dur": 0.35 },
        { "i": 8, "voice": "pluck", "note": "C4", "dur": 0.12 }
      ]
    }
  },
  "sections": [{ "track": "pulse", "bars": 6 }]
}

    A complete score: trimmed from examples/demo-spec.json, and it renders exactly as shown. Tracks are keyed by name; each step names its sixteenth-note slot (i), a voice, and a note and dur for pitched voices. The full format is in docs/M2-INTERFACE.md.

    Get started

    In the browser, nothing to install: open the Audition Room and paste a score. On your machine (Node 22+): clone, install, render a demo score.

    git clone https://github.com/lerugray/house-band.git
cd house-band
npm ci
node bin/house-band.mjs render examples/demo-spec.json -o demo.wav

    Open the GitHub repo for the README sections on render, samples, and co-write.
